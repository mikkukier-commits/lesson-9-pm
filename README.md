# MLflow + Prometheus: PM analysis

## Опис задачі
Проєкт аналізує п'ять експериментів MLflow для класифікації датасету Iris та експортовані в Prometheus метрики `mlflow_accuracy` і `mlflow_loss`.

## Файли
- `pm_report.md` — аналіз runs, вибір кандидата, Prometheus/MLflow, production-readiness checklist, ризики та PM-рішення.
- `screenshots/` — папка для скриншотів із MLflow UI та Prometheus/Grafana.

## Використані вхідні дані
Використано наданий документ «Вхідні дані для завдання: MLflow + Prometheus». Він містить параметри й метрики п'яти runs, інформацію про artifact для `rf-depth3`, назви Prometheus metrics і пояснення розриву графіка приблизно о 08:34 UTC.

Самі файли зображень скриншотів не були включені до доступних матеріалів, тому папка `screenshots/` містить інструкцію, які зображення слід додати перед здачею. Вигадані скриншоти не створювалися.

## Обраний кандидат і рішення
- Кандидат: `rf-depth3`
- Accuracy: `0.956`
- Loss: `0.141`
- Model artifact: є
- PM-рішення: `Need more experiments` перед staging; production поки не рекомендується.

## Основні ризики
- Мала тестова вибірка.
- Немає artifacts для інших runs.
- У вхідній таблиці немає фактичних run ID.
- Не підтверджено безпосереднім зіставленням, що Prometheus значення збігаються з MLflow.
- Не надано критеріїв promotion, owner рішення, rollback-плану та production monitoring.

## Що потрібно зробити перед production
Провести додаткову перевірку стабільності, проаналізувати якість по класах, зафіксувати run ID і версії коду/даних, звірити метрики в MLflow і Prometheus, погодити acceptance criteria, ownership, rollback і моніторинг.

## Перед здачею
1. Додайте справжні скриншоти до `screenshots/`, якщо вони доступні.
2. Перевірте, чи потрібно додати фактичний `run_id` із MLflow UI.
3. За потреби перейменуйте архів відповідно до формату `ДЗ9_PM_Прізвище_Імʼя.zip`.
